Signed inBasic

What happens when you submit

  1. startSubmission opens a record for the survey slug, with device type and source.
  2. saveResponse runs once per question and upserts, so going back and changing an answer is safe.
  3. completeSubmission stamps the submission as completed.
  4. scoreCatabolicCrisis or scoreFunctionalScorecard scores on the server, writes a result row and a pathway row, and returns the payload.
  5. The page navigates to the next screen. Scoring never runs in the browser.

Scoring rules already live

Catabolic: three scored questions (0–4 each), total 0–12. Bands: 0–1 no flag, 2–3 watch, 4–6 active recovery, 7+ high risk. Overrides lift the band when a single answer is severe, and a "more than one driver" answer with a total of 6 or more forces high risk.

Functional: 24 questions scored 1–5, total 24–120, five bands from high risk to resilient. Category and pillar roll-ups pick the weakest pillar and the lowest category.

Worth knowing: the catabolic result reaches the results page through sessionStorage, so that card disappears if the tab is closed. Moving it into the stored result is part of Step 3.

The framework the app is built around

Everything in this section is drawn from config/framework-taxonomy.json, the same file the Convex seed reads. All four pillars and all twelve categories are visible; nothing is locked.

Four-pillar matrix

Diamond orientation: E top, N right, R bottom, B left. Scored and drawn at pillar level, with a 5-2-3-2 category split underneath.

GMMBB axis

The diagnostic lens, drawn as a pentagon: Gut, Muscle, Metabolic, Bone, Brain. Larger discs carry more weight.

Before it runs

What is open, and who owns it

Waiting on you

  • A Convex deploy key from a new project, or one interactive npx convex dev login.
  • Clerk publishable key, secret key and JWT issuer domain.
  • CONVERGENCE-PATTERNS.md and CROSS-CUTTING-NODES.md from the canonical folder.
  • Clinical review of scoring bands before assessments ship.

Gaps in the existing code

  • Result buttons point to /pathways/… routes that do not exist, so they redirect home.
  • Results show raw keys such as recovery_stress instead of labels.
  • seedSurveyContent is never called, so a fresh database has no surveys.
  • pathwayLabel stores the raw key instead of the label.
  • src/lib/scoring/ is unused and duplicates the server scoring.
  • No automated tests anywhere.

Naming drift to reconcile

  • survey-schema.json says balance_brain; the CTA map and framework say balance_brain_health. A TODO alias hides this in results.ts.
  • Survey categories do not yet carry the P#-C# ids, and list endurance before strength.
  • The branded interface is not applied anywhere yet.
